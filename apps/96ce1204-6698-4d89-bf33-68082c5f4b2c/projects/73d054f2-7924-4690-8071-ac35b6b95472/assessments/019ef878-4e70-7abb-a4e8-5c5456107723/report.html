CRA: Use of insecure random number generator java.util.Random
 Mandatory 5
FilePosition
ruoyi-gateway/src/main/java/com/ruoyi/gateway/config/KaptchaTextCreator.javaLine 19, Col 0
ruoyi-common/ruoyi-common-core/src/main/java/com/ruoyi/common/core/utils/uuid/UUID.javaLine 6, Col 0
ruoyi-gateway/src/main/java/com/ruoyi/gateway/config/KaptchaTextCreator.javaLine 3, Col 0

Explanation

EU Cyber Resilience Act (Annex I, Part I, Section 2(c)) requires the use of state of the art cryptographic mechanisms, which includes the use of cryptographically secure random number generators (CSPRNG).

java.util.Random uses a linear congruential generator (LCG) which is not cryptographically secure. Its output is predictable given enough observations, making it unsuitable for:

  • Token/session ID generation
  • Nonce/IV generation for encryption
  • Salt generation for password hashing
  • Any security-sensitive random value generation

Recommended actions:

  • Replace new Random() with new SecureRandom() for any security-relevant random number generation.
  • Replace Math.random() with SecureRandom.nextDouble() for security use cases.
  • Replace ThreadLocalRandom.current() with SecureRandom for security contexts.
  • Use java.security.SecureRandom which provides a CSPRNG backed by the OS entropy source.

CRA: Use of weak hash algorithm MD5
 Mandatory 5
FilePosition
ruoyi-common/ruoyi-common-core/src/main/java/com/ruoyi/common/core/utils/uuid/UUID.javaLine 119, Col 0

Explanation

EU Cyber Resilience Act (Annex I, Part I, Section 2(c)) requires that products protect the confidentiality and integrity of data using encryption and hashing mechanisms that reflect the state of the art.

MD5 is a cryptographically broken hash algorithm. It is vulnerable to collision attacks and must not be used for:

  • Password hashing
  • Digital signatures
  • Data integrity verification
  • Certificate validation

Recommended actions:

  • Replace MessageDigest.getInstance("MD5") with MessageDigest.getInstance("SHA-256") or MessageDigest.getInstance("SHA-3-256") for general hashing.
  • For password hashing, use bcrypt, scrypt, Argon2, or PBKDF2 instead.
  • For HMAC operations, use HmacSHA256 or HmacSHA3-256.

java.net.URL Constructors Are Deprecated
 Mandatory 3

Explanation

The java.net.URL constructors are deprecated in JDK 20 release.

Developers are encouraged to use java.net.URI to parse or construct a URL. In cases where an instance of java.net.URL is needed to open a connection, java.net.URI can be used to construct or parse the URL string, possibly calling URI::parseServerAuthority() to validate that the authority component can be parsed as a server-based authority, and then calling URI::toURL() to create the URL instance.

A new method, URL::of(URI, URLStreamHandler) is provided for the advanced usages where there is a need to construct a URL with a given custom stream handler.
